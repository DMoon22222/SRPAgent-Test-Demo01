## 可执行的复核顺序

1. 按 [交付说明](../local_v2_handoff_v0.4.0.md)安装选定固定版本与共同基线；从公开工厂取得能力，核对配置与实例实际来源。规则模式无需模型凭据。
2. 执行该版本的契约、静态和诊断预检。0.4.0 的 SDK 离线测试入口为 B `python_service/tests/test_local_v2_claude.py`；0.3.1 的精确快照/P2 工具应在旧固定提交运行，不能直接套在修改后的 0.4.0。
3. 核对实际 Docker image ID、Python/pytest、代码/测试/config 哈希及隔离政策；运行正式材料中的公开测试、诊断、连续修复和必要异常分支。所有目标代码交 B 沙箱执行。
4. 如选 SDK 模式，先核验 model_calls/输入输出/rounds 和期限授权，再执行实际 API 验证；保留实际/未知用量及受控原件，记录明确拒绝与未知状态。
5. 按里程碑核对隐藏最终验收、公开接收视图、最终失败停止和预算结算；形成 INTB-001 实际意见。再与真实 A/C 配合进入 P3 自然全链及规定分支。
